Pourquoi mon site n'est-il pas indexé dans Google — 12 raisons et comment les corriger

Vous avez lancé votre site, attendu quelques semaines — et rien dans Google. Ou certaines pages apparaissent dans la recherche, tandis que d'autres semblent inexistantes. Nous couvrons les 12 raisons les plus courantes pour lesquelles Google ignore un site ou des pages individuelles — et ce qu'il faut faire exactement dans chaque cas.

D'abord : Vérifiez s'il y a un problème

Avant de chercher la cause, assurez-vous que le problème existe réellement. Tapez dans Google :

site:votresite.com

S'il n'y a pas de résultats ou significativement moins que le nombre de pages sur le site — continuez à lire.

Ouvrez également Google Search Console → Indexation → Pages. Là, Google explique lui-même pourquoi chaque page n'est pas indexée.

12 raisons et solutions

Raison 01

Tag noindex sur la page

La raison la plus courante de "l'invisibilité" dans Google. Le code de la page contient une balise qui interdit directement l'indexation :

<meta name="robots" content="noindex">

Une telle balise peut avoir été ajoutée par erreur lors du développement, ou si le CMS définit automatiquement noindex pour certains types de pages (tags, catégories, pages de recherche).

✓ Solution

Vérifiez le code de chaque page (Ctrl+U dans le navigateur, recherchez "noindex"). Dans WordPress — vérifiez Yoast SEO ou RankMath, les paramètres de visibilité pour chaque type de publication.

Raison 02

Bloqué dans robots.txt

Le fichier robots.txt peut bloquer Googlebot d'explorer des sections entières du site. Ouvrez votresite.com/robots.txt et recherchez des lignes comme :

Disallow: / Disallow: /blog/
✓ Solution

Si la ligne Disallow: / — cela bloque l'ensemble du site. Supprimez ou remplacez par Disallow: (valeur vide — autorise tout). Vérifiez via l'outil de test robots.txt dans Search Console.

Raison 03

Site protégé par mot de passe ou en maintenance

Si le site nécessite une autorisation ou renvoie un code 503 — Googlebot ne peut pas accéder au contenu. C'est typique pour les nouveaux sites lancés "silencieusement".

✓ Solution

Assurez-vous que le site est accessible sans autorisation. Vérifiez via Google Search Console → Inspection d'URL → "Tester l'URL en direct".

Raison 04

Budget de crawl faible — Googlebot ne peut pas suivre

Google attribue un certain "budget de crawl" à chaque site — le nombre de pages qu'il est prêt à explorer dans un temps donné. Pour les nouveaux sites et les petits sites, ce budget est minimal.

Si le site a des milliers de pages ou change fréquemment — Googlebot ne peut tout simplement pas explorer toutes les URL.

✓ Solution

Utilisez l'API d'indexation Google pour les pages prioritaires. Supprimez les URL "junk" du sitemap (tags avec 1 article, catégories vides, requêtes de recherche). Vérifiez la vitesse du site — un site lent obtient un budget de crawl plus petit.

Raison 05

Contenu dupliqué et canonical

Si plusieurs URL ont le même contenu ou un contenu très similaire, Google choisit une URL "canonique" et peut ignorer les autres. Problèmes courants :

  • Versions HTTP et HTTPS du site sans redirection
  • Versions www et non-www
  • Pages avec et sans slash final : /page et /page/
  • Paramètres d'URL : /page?utm_source=... au lieu de /page
✓ Solution

Définissez la balise canonique sur toutes les pages pointant vers la version "principale". Configurez des redirections 301. Dans Search Console, vérifiez le rapport "Découvert — actuellement non indexé" — il contient souvent des informations sur les doublons.

Raison 06

Contenu mince ou de faible qualité

Google peut refuser d'indexer des pages avec peu de texte unique. À risque :

  • Pages avec moins de 300–500 mots
  • Contenu généré automatiquement
  • Pages modèles avec un contenu unique minimal (tags, mois)
  • Contenu copié d'autres sites
✓ Solution

Soit améliorez considérablement le contenu, soit fermez ces pages avec la balise noindex. Il vaut mieux avoir 50 pages indexées de qualité que 500 "invisibles".

Raison 07

Erreurs de serveur — codes 4xx et 5xx

Si Googlebot reçoit des erreurs lors de la demande de pages — il cesse de les visiter et les supprime de l'index. Les codes 404 (non trouvé), 500 (erreur de serveur), 503 (service indisponible) — tout cela réduit l'activité de crawl.

✓ Solution

Search Console → Indexation → Pages → "Non trouvé (404)" et "Erreur de serveur (5xx)". Corrigez ou configurez des redirections 301 pour les pages supprimées. Vérifiez les journaux du serveur pour des erreurs massives.

Raison 08

Vitesse de chargement de page lente

Google prend en compte les Core Web Vitals lors du classement et de la détermination du budget de crawl. Un site très lent (LCP > 4 secondes) obtient un budget de crawl plus petit.

✓ Solution

Vérifiez via PageSpeed Insights (pagespeed.web.dev). Métriques clés : LCP (Largest Contentful Paint) inférieur à 2,5s, FID inférieur à 100ms, CLS inférieur à 0,1. Optimisez les images, activez la mise en cache, connectez un CDN.

Raison 09

Aucun lien vers la page

Googlebot trouve de nouvelles pages principalement par le biais de liens. S'il n'y a aucun lien interne ou externe vers une page — elle peut rester "invisible" même si elle est dans le sitemap.

✓ Solution

Ajoutez des liens internes depuis d'autres pages populaires. Assurez-vous que les nouveaux articles apparaissent dans les sections "À lire aussi", "Nouvelles publications", etc. Ou utilisez l'API d'indexation pour notifier directement Google.

Raison 10

Le rendu JavaScript bloque le contenu

Si votre site est construit sur React, Vue ou Angular et que le contenu est rendu uniquement côté client — Googlebot peut ne pas voir le texte des pages. Il "voit" seulement une coquille HTML vide.

✓ Solution

Configurez le rendu côté serveur (SSR) ou la génération de site statique (SSG). Vérifiez via Search Console → Inspection d'URL → "Voir la page explorée" — cela montre exactement ce que voit Googlebot.

Raison 11

Domaine jeune — il a juste besoin de temps

Pour les nouveaux domaines (moins de 6 mois), Google ajoute généralement les pages à l'index plus lentement. C'est normal — les algorithmes vérifient la fiabilité des nouvelles ressources.

✓ Solution

Obtenez quelques liens externes de qualité (de sites autoritaires dans votre niche). Publiez régulièrement du contenu de qualité. Utilisez l'API d'indexation pour accélérer les choses. Enregistrez le site dans Search Console et ajoutez un sitemap.

Raison 12

Filtre ou pénalité de Google

Dans de rares cas, un site peut recevoir une pénalité manuelle de l'équipe Google (pour manipulation de liens, contenu spam, cloaking, etc.) ou une pénalité algorithmique automatique.

✓ Solution

Vérifiez Search Console → Sécurité et actions manuelles → Actions manuelles. S'il y a une pénalité — corrigez les violations et soumettez une demande de révision. Pour les filtres algorithmiques — améliorez la qualité du contenu et le profil de lien.

Plan d'action étape par étape

Si votre site n'est pas indexé — agissez dans cet ordre :

  1. Vérifiez robots.txt — assurez-vous qu'il n'y a pas de blocages
  2. Vérifiez la balise noindex sur les pages problématiques
  3. Ouvrez Search Console → Pages → lisez les raisons d'exclusion
  4. Vérifiez l'accessibilité du site et les codes de réponse du serveur
  5. Vérifiez la vitesse via PageSpeed Insights
  6. Éliminez les problèmes trouvés
  7. Envoyez les URL via l'API d'indexation Google pour accélérer l'indexation
