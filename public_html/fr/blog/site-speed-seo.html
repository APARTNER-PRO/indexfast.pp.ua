Vitesse du site et SEO : Core Web Vitals, LCP, INP, CLS en 2026

Google prend officiellement en compte les Core Web Vitals dans le classement depuis 2021. LCP, INP, CLS — trois métriques qui déterminent si votre site obtient un bonus ou une pénalité dans la recherche. Nous analysons chaque métrique, les causes de mauvaises performances et des solutions spécifiques.

Pourquoi la vitesse du site est-elle critique pour le SEO

Depuis 2021, Google prend officiellement en compte les Core Web Vitals pour le classement — ce sont des métriques de vitesse et d'utilisabilité mesurées dans des conditions réelles sur des appareils utilisateurs réels. Les sites qui passent le seuil des Core Web Vitals reçoivent un léger coup de pouce dans le classement.

Mais l'impact indirect est plus important : site lent → taux de rebond plus élevé → moins de temps sur la page → signaux comportementaux moins bons → classements plus bas. De plus, Google alloue un budget de crawl plus petit aux sites lents.

Core Web Vitals : trois métriques clés

LCP — Largest Contentful Paint

Temps jusqu'à l'apparition du plus grand élément visible (généralement une image principale ou un titre). Montre quand l'utilisateur voit le contenu principal.

  • Bon : jusqu'à 2,5 secondes
  • Nécessite une amélioration : 2,5–4 s
  • Mauvais : plus de 4 secondes

Principales causes d'un mauvais LCP : grandes images non compressées, serveur lent, ressources bloquant le rendu (JS, CSS), absence de CDN.

INP — Interaction to Next Paint

Temps de réponse à une interaction utilisateur (clic, tap, saisie). Remplace FID en mars 2024.

  • Bon : jusqu'à 200 ms
  • Nécessite une amélioration : 200–500 ms
  • Mauvais : plus de 500 ms

CLS — Cumulative Layout Shift

Déplacement total des éléments pendant le chargement. Le contenu "saute" lorsque des images ou des publicités sont chargées.

  • Bon : jusqu'à 0,1
  • Nécessite une amélioration : 0,1–0,25
  • Mauvais : plus de 0,25
🔧 Comment vérifier

pagespeed.web.dev — entrez l'URL et obtenez un rapport détaillé sur les trois métriques pour mobile et desktop. Vérifiez également Search Console → Core Web Vitals pour des données d'appareils réels.

Optimisation des images — Le gain le plus rapide

Les images sont la principale raison d'un LCP lent. Quelques règles :

  • Format WebP — 25–35 % plus petit que JPEG à qualité égale
  • Chargement paresseux — loading="lazy" pour les images en dessous de la première page
  • Dimensions dans HTML — spécifiez toujours la largeur et la hauteur pour éviter le CLS
  • Précharger l'image LCP — ajoutez <link rel="preload" as="image"> pour l'image principale
  • CDN pour les images — Cloudflare Images ou un équivalent pour une livraison mondiale

Vitesse du serveur et TTFB

TTFB (Time to First Byte) — temps jusqu'au premier octet de la réponse du serveur. Google considère un TTFB jusqu'à 800 ms comme bon.

  • Mise en cache — les pages doivent être renvoyées depuis le cache, pas générées à chaque fois
  • Hébergement — VPS ou hébergement cloud est beaucoup plus rapide que partagé
  • CDN — Cloudflare réduit le TTFB pour les visiteurs de différents pays gratuitement
  • Bases de données — les requêtes SQL lentes sont la cause la plus fréquente d'un mauvais TTFB

Optimisation JavaScript et CSS

Le navigateur ne peut pas rendre la page tant que les ressources bloquant le rendu sont en cours de téléchargement et d'exécution :

  • Déplacez le JS à la fin du corps ou ajoutez defer / async
  • Extraire le CSS critique (above-the-fold) et l'inclure dans le head
  • Minimiser et compresser les fichiers JS et CSS
  • Supprimer le CSS inutilisé (onglet Coverage dans DevTools)
  • Diviser le gros JS en morceaux et les charger paresseusement
⚠ Scripts tiers — Le principal ennemi de la vitesse

Google Analytics, Facebook Pixel, chats, réseaux publicitaires — chaque script tiers ajoute 100–500 ms au temps de chargement. L'audit des scripts tiers via l'onglet Lighthouse Network est une étape obligatoire.

Polices et vitesse

  • Utilisez font-display: swap — le texte est visible immédiatement, la police se charge en arrière-plan
  • Préconnectez-vous à fonts.googleapis.com et fonts.gstatic.com
  • Limitez les variantes de polices — uniquement les poids réellement utilisés
  • Envisagez des polices système pour le texte critique (temps de chargement nul)

Optimisation mobile

Google utilise l'indexation Mobile-First — il indexe la version mobile du site comme principale. Par conséquent, la vitesse mobile est plus importante que la version desktop.

  • Vérifiez la PageSpeed mobile séparément de la version desktop
  • Testez sur des appareils réels, pas seulement dans DevTools
  • Boutons d'au moins 48x48px pour un tap facile
  • Évitez le défilement horizontal
  • Les popups ne doivent pas obscurcir le contenu principal (pénalité pour interstitiels intrusifs)

Liste de contrôle de la vitesse du site

  • LCP inférieur à 2,5 secondes sur mobile
  • INP inférieur à 200 ms
  • CLS inférieur à 0,1
  • Toutes les images au format WebP
  • chargement paresseux pour les images en dessous de la première page
  • CDN connecté (Cloudflare ou équivalent)
  • JS déplacé à la fin ou defer ajouté
  • Mise en cache du serveur configurée
  • TTFB inférieur à 800 ms
  • font-display: swap pour les polices personnalisées
  • Audit des scripts tiers terminé
