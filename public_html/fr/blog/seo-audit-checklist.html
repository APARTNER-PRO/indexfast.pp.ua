Audit SEO du site : Liste de contrôle complète de 50 points en 2026

Un audit SEO régulier est le seul moyen de détecter les problèmes avant qu'ils n'affectent significativement le trafic. 50 points de contrôle spécifiques : des robots.txt et Core Web Vitals à E-E-A-T et la qualité des backlinks.

Qu'est-ce qu'un audit SEO et pourquoi est-il nécessaire

Un audit SEO est une vérification systématique d'un site web pour s'assurer de sa conformité aux exigences des moteurs de recherche. Il révèle des erreurs techniques, des problèmes de contenu et des opportunités manquées pour la croissance du classement. Un audit régulier (une fois par trimestre) vous permet de détecter la dégradation avant qu'elle n'affecte significativement le trafic.

Cette liste de contrôle se compose de 50 éléments regroupés par catégories. Parcourez-les séquentiellement — chaque élément non corrigé représente un risque pour la visibilité du site dans les recherches.

SEO technique (Points 1–15)

  • 1. HTTPS — le site doit s'ouvrir uniquement via https://. Vérifiez les redirections depuis http://
  • 2. WWW/non-WWW — une version doit rediriger vers l'autre (301)
  • 3. robots.txt — le fichier existe, ne bloque pas les sections importantes, accessible sans autorisation
  • 4. Sitemap.xml — existe, à jour, enregistré dans Search Console
  • 5. Codes d'état — pas d'erreurs 200 sur les pages 404 (soft 404)
  • 6. Redirections — les chaînes de redirection ne dépassent pas 2 étapes
  • 7. Vitesse de chargement — LCP inférieur à 2,5s sur mobile (PageSpeed)
  • 8. Core Web Vitals — FID/INP inférieur à 200ms, CLS inférieur à 0,1
  • 9. Version mobile — le site s'affiche correctement sur toutes les tailles d'écran
  • 10. Données structurées — Schema.org pour les principaux types de pages
  • 11. Hreflang — correctement configuré s'il y a du contenu multilingue
  • 12. Tags canoniques — chaque page pointe vers elle-même ou la version principale
  • 13. Pagination — rel="next"/"prev" ou canonique vers la première page
  • 14. Erreurs d'exploration — vérifiez Search Console pour les erreurs 4xx et 5xx
  • 15. Fichiers journaux — Googlebot visite régulièrement les pages importantes
💡 Vérification technique rapide

Entrez l'adresse du site sur pagespeed.web.dev — obtenez immédiatement les scores Core Web Vitals pour mobile et desktop. C'est la première étape de tout audit technique.

Indexation (Points 16–22)

  • 16. Nombre de pages indexées — comparez site: avec le nombre réel de pages
  • 17. Noindex sur les pages importantes — vérifiez s'il n'y a pas de noindex accidentel
  • 18. Couverture de Search Console — examinez les catégories "Erreur" et "Exclu"
  • 19. Pages orphelines — pages sans liens internes dans le rapport d'exploration
  • 20. Doublons dans l'index — site: montrera s'il y a plusieurs versions d'une même page
  • 21. Sitemap vs Index — combien d'URL du sitemap sont réellement indexées
  • 22. API d'indexation — l'envoi automatique de nouvelles URL est-il configuré
⚠ Point critique : fuite de noindex

L'erreur la plus coûteuse en SEO est lorsque le noindex passe en production depuis l'environnement de test. Vérifiez cela en premier après chaque déploiement. Search Console montrera une forte baisse des pages indexées.

SEO on-page (Points 23–35)

  • 23. Tags de titre — uniques, contiennent le mot-clé, 50–60 caractères
  • 24. Meta description — uniques, 120–155 caractères, contient un CTA
  • 25. H1 — un H1 par page, contient le mot-clé
  • 26. Structure des titres — hiérarchie logique H1 → H2 → H3
  • 27. Mots-clés dans le contenu — utilisation naturelle, sans bourrage de mots-clés
  • 28. Longueur du contenu — minimum 300 mots, pour les requêtes concurrentielles 1000+
  • 29. Unicité du contenu — pas de doublons avec d'autres pages du site
  • 30. Images — balises alt remplies, fichiers optimisés (WebP)
  • 31. Liens internes — les pages importantes ont des liens d'autres pages
  • 32. Texte d'ancrage — descriptif, pas "cliquez ici" ou "lire plus"
  • 33. Structure des URL — courte, claire, contient le mot-clé
  • 34. Fil d'Ariane — navigation Breadcrumb avec Schema.org
  • 35. Contenu obsolète — les articles de plus de 2 ans nécessitent une mise à jour

Contenu et E-E-A-T (Points 36–42)

  • 36. Auteur du contenu — auteur indiqué avec biographie et liens sociaux
  • 37. Date de publication et de mise à jour — visible sur la page
  • 38. Sources et références — liens vers des sources autorisées lorsque cela est approprié
  • 39. Pages À propos et Contact — informations détaillées sur l'entreprise
  • 40. Politique de confidentialité et Conditions — documents à jour
  • 41. Avis et preuves sociales — avis réels sur le site
  • 42. Contenu mince — pages de moins de 300 mots sans réelle valeur

Liens externes (Points 43–47)

  • 43. Nombre de backlinks — vérifiez via Ahrefs ou Google Search Console
  • 44. Qualité des donateurs — liens provenant de sites thématiques autorisés
  • 45. Liens toxiques — liens spam provenant de sites de faible qualité
  • 46. Profil de texte d'ancrage — ancres diverses, pas de bourrage d'expressions exactes
  • 47. Backlinks cassés — liens vers des pages supprimées ou modifiées de votre site

Analytics et Suivi (Points 48–50)

  • 48. Google Analytics 4 — installé, suit correctement les conversions
  • 49. Search Console — site vérifié, sitemap ajouté, pas de messages d'erreur
  • 50. Suivi régulier — revue hebdomadaire des indicateurs clés : trafic, classements, indexation

Priorisation des corrections

Ne tentez pas de tout corriger en même temps. Priorisez les tâches :

  • Critique (cette semaine) — noindex sur les pages importantes, blocages robots.txt, erreurs 5xx massives
  • Important (ce mois-ci) — vitesse du site, doublons de contenu, balises canoniques manquantes
  • Désirable (le trimestre prochain) — mise à jour du contenu ancien, création de liens, Schema.org
