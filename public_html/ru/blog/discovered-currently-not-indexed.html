"Обнаружено, но не проиндексировано": почему Google игнорирует ваши страницы и как это исправить

Вы открываете Google Search Console и видите список страниц со статусом "Обнаружено — в настоящее время не проиндексировано". Проходят дни, недели — страницы всё ещё не в Google. Это одна из самых распространённых и болезненных проблем для владельцев сайтов. Разбираемся, почему это происходит и как исправить раз и навсегда.

Что на самом деле означает "Обнаружено — в настоящее время не проиндексировано"

Этот статус означает: Google нашёл URL — через sitemap или ссылку — но решил его пока не сканировать. То есть: Google знает, что страница существует, но выбрал её не посещать.

Ключевое слово — "выбрал". Это не техническая ошибка. Это решение Google, основанное на crawl budget вашего сайта и приоритете страницы.

💡 Простая аналогия

Представьте почтальона, которому нужно доставить 1000 писем. Он знает ваш адрес, но если считает доставку низкоприоритетной — кладёт письмо в конец очереди. Ваша страница ждёт месяцами, пока страницы конкурентов индексируются в тот же день.

Реальные причины, почему Google пропускает ваши страницы

Большинство SEO-гайдов дают размытые ответы вроде "улучшите качество контента". Реальность конкретнее:

  • Исчерпан crawl budget. Google выделяет ограниченное количество сканирований на сайт в день. Большие сайты с тысячами страниц часто исчерпывают бюджет — новые страницы остаются в очереди.
  • Низкий авторитет домена. Новые сайты или сайты с малым количеством ссылок получают меньший crawl budget.
  • Медленный ответ сервера. Если сервер отвечает медленно (более 500мс), сканер Google замедляется или останавливается.
  • Слишком много малоценных страниц. Если в sitemap есть пагинированные страницы фильтров, теги или дубликаты — Google тратит бюджет на них.
  • Нет внутренней перелинковки. Страницы, которые есть только в sitemap, но не имеют внутренних ссылок — считаются низкоприоритетными.
  • Недавно опубликована. Новые страницы на слабых сайтах могут ждать в очереди "обнаружено" месяцами.

Что НЕ делать (распространённые ошибки)

Когда владельцы видят этот статус, они часто делают хуже:

  • Постоянно запрашивают переиндексацию через "Проверка URL" в Search Console (лимит 10-15 URL в день)
  • Закрывают и открывают страницы в robots.txt в надежде на переобход
  • Удаляют страницы из sitemap думая, что это поможет
  • Бесконечно ждут — это может длиться месяцами
⚠ Ловушка ручной отправки URL

Кнопка "Запросить индексацию" в Search Console выглядит как решение, но имеет жёсткие ограничения. Можно отправить 10-15 URL в день. Для сайта с сотнями проблемных страниц — это практически бесполезно.

Настоящее решение: заставить Google индексировать через официальный API

Google предоставляет Indexing API именно для того, чтобы сайты могли уведомлять Google о важных страницах для немедленного сканирования. Когда вы отправляете запрос через API — Google приоритизирует сканирование этого URL — обычно в течение 24-48 часов.

Это не обходной путь. Это официальный рекомендованный Google метод ускорения индексации.

Шаг 1: Правильно настройте Google Search Console

Проверьте сайт в Google Search Console. Убедитесь, что есть корректный sitemap. Проверьте раздел "Ручные действия" — ручное наказание полностью заблокирует индексацию.

Шаг 2: Сначала исправьте технические проблемы

Перед отправкой исправьте базовые проблемы: время загрузки до 3 секунд, добавьте внутренние ссылки к изолированным страницам, удалите малоценный контент из sitemap.

Шаг 3: Используйте Google Indexing API для отправки страниц

Здесь происходит реальное ускорение. Через Indexing API можно уведомить Google о 200 URL в день — Googlebot сканирует их с высоким приоритетом. Разница:

❌
Без API: 2-8 недель
✅
С API: 24-48 часов

Как сделать это без написания кода

Ручная настройка Google Indexing API требует: проект Google Cloud, Service Account, JSON-ключ, написание API-запросов, автоматизация. Для не-разработчиков — значительный технический барьер.

IndexFast убирает всю эту сложность. Вы один раз подключаете Google Search Console, добавляете URL sitemap — и IndexFast автоматически:

  • Читает sitemap и обнаруживает новые или обновлённые URL
  • Отправляет их через Google Indexing API от вашего имени
  • Автоматически управляет суточной квотой (200 URL/день)
  • Показывает детальный лог: какие страницы отправлены и когда
  • Запускается по расписанию — каждая новая страница индексируется без вашего участия

Для страниц со статусом "Обнаружено" — можно массово отправить их сразу. Большинство пользователей видят эти страницы в Google через 24-48 часов.

Какие страницы отправлять первыми

Не пытайтесь индексировать всё сразу. С квотой 200 URL/день будьте стратегичны:

  1. Сначала страницы, приносящие доход — товары, услуги, посадочные страницы
  2. Свежий контент — новые статьи блога, новости
  3. Недавно обновлённые страницы — если существенно изменили контент
  4. Пропустите тонкие страницы — пагинация, теги, фильтры

Долгосрочная стратегия: не допустить повторения проблемы

После решения текущего завала — настройте систему чтобы новые страницы больше не зависали:

  • Автоматическая ежедневная индексация: Настройте IndexFast проверять sitemap каждый день и отправлять новые URL. Каждая опубликованная страница индексируется в тот же день.
  • Внутренняя перелинковка: При публикации нового контента — ссылайтесь на него с 2-3 популярных существующих страниц.
  • Чистота sitemap: Удалите страницы, которые не стоит индексировать (тонкий контент, дубликаты). Это даст Google больше бюджета для важных страниц.
  • Мониторинг Search Console: Еженедельно проверяйте Покрытие > "Обнаружено — в настоящее время не проиндексировано". Если количество растёт — немедленно расследуйте.

Итог: что сделать прямо сейчас

  1. Откройте Google Search Console → Страницы → "Обнаружено — в настоящее время не проиндексировано"
  2. Зафиксируйте сколько страниц и какие из них наиболее важные
  3. Исправьте очевидные технические проблемы (медленная загрузка, отсутствие ссылок)
  4. Подключите IndexFast и отправьте проблемные страницы через Indexing API
  5. Настройте автоматическую индексацию чтобы будущие страницы не зависали
  6. Проверьте через 48-72 часа — большинство страниц должны появиться в Google
