Website-Indexierung nach dem Redesign: So verlieren Sie Traffic

Ein Redesign ohne angemessene Vorbereitung kann Jahre an angesammeltem SEO-Traffic in wenigen Wochen zerstören. 301-Weiterleitungen, eine aktualisierte Sitemap, Massenreindexierung über die API — wir erläutern jeden Schritt, damit Google die neue Website so schnell wie möglich sieht.

Was passiert mit der Indexierung nach einem Redesign

Das Redesign einer Website ist einer der riskantesten Momente für SEO. Wenn sich URLs geändert haben, die Seitenstruktur anders ist oder neue technische Lösungen entstanden sind — benötigt Google Zeit, um Ihre Website neu zu bewerten.

Ein typisches Bild nach dem Start eines neuen Designs: Der Traffic bleibt in der ersten Woche stabil, dann ein starker Rückgang von 30–70% und ein langer Wiederherstellungsprozess. Die meisten dieser Probleme können verhindert oder erheblich reduziert werden.

Vor dem Start: Vorbereitung der Indexierung

Das Wichtigste, was zu tun ist, bevor die neue Website veröffentlicht wird:

  1. Audit der aktuellen URLs — machen Sie einen Screenshot oder CSV aller indexierten Seiten (über die Search Console oder den site: Operator)
  2. Weiterleitungspläne — für jede alte URL notieren Sie die neue. Wenn /product/123 zu /products/widget-blue wird, benötigen Sie eine 301-Weiterleitung
  3. Test-Crawl — vor dem Start crawlen Sie die Staging-Umgebung mit Screaming Frog oder einem Äquivalent
  4. Speichern Sie die Sitemap der alten Website — Sie benötigen sie als Referenz
⚠ Der teuerste Fehler beim Redesign

Änderung aller URLs ohne 301-Weiterleitungen. Google verliert alle angesammelten Signale für alte Seiten. Neue URLs beginnen von vorne. Die Wiederherstellung kann 6–12 Monate dauern.

Starttag: Erste Schritte

Nach der Veröffentlichung der neuen Website sind die ersten 24 Stunden entscheidend:

  • Überprüfen Sie alle 301-Weiterleitungen (curl oder Redirect Checker)
  • Stellen Sie sicher, dass robots.txt die neue Website nicht blockiert
  • Überprüfen Sie, ob noindex nicht aus der Testumgebung übrig geblieben ist
  • Aktualisieren Sie sitemap.xml — sie muss die neuen URLs widerspiegeln
  • Fügen Sie die aktualisierte Sitemap zur Search Console hinzu

Massenreindexierung nach dem Redesign

Selbst mit perfekten Weiterleitungen benötigt Google Zeit, um die gesamte Website zu crawlen und die Daten zu aktualisieren. Für eine große Website dauert dies Wochen. Die Google Indexing API kann den Prozess beschleunigen.

Algorithmus der Maßnahmen:

  1. Aktualisieren Sie sitemap.xml mit den neuen URLs
  2. Reichen Sie alle Seiten über die Google Indexing API ein (IndexFast erledigt dies automatisch)
  3. Für Seiten mit geändertem Inhalt, reichen Sie sie erneut mit dem Typ URL_UPDATED ein
  4. Für gelöschte Seiten, reichen Sie URL_DELETED ein, damit Google sie sofort aus dem Index entfernt
💡 URL_UPDATED vs URL_DELETED

Die Indexing API unterstützt zwei Anfragetypen: URL_UPDATED (indexieren oder aktualisieren) und URL_DELETED (aus dem Index entfernen). Nach einem Redesign ist es entscheidend, URL_DELETED für Seiten einzureichen, die nicht mehr existieren, da Google sie sonst wochenlang im Zustand eines sanften 404 hält.

Überwachung nach dem Start

Die ersten 4 Wochen nach dem Redesign sind eine kritische Phase. Überwachen Sie:

  • Search Console → Abdeckung — die Anzahl der indexierten Seiten sollte nicht stark sinken
  • Search Console → Leistung — Klicks und Impressionen. Ein Rückgang von 20%+ weist auf ein Problem hin
  • Crawl-Fehler — 404 auf alten URLs (überprüfen Sie die Weiterleitungen)
  • site: Vergleich — eine Woche und einen Monat nach dem Start

Was tun, wenn der Traffic nach dem Redesign sinkt

  • Überprüfen Sie robots.txt — möglicherweise ist ein ganzer Abschnitt blockiert
  • Überprüfen Sie die kanonischen Tags — sie könnten auf nicht existierende oder falsche URLs verweisen
  • Überprüfen Sie 301-Weiterleitungen — Weiterleitungsketten (A→B→C) reduzieren die Signalübertragung
  • Vergleichen Sie die Struktur der neuen und alten Sitemap — finden Sie fehlende Seiten
  • Reichen Sie problematische URLs erneut über die Indexing API ein

Checkliste für die Indexierung nach dem Redesign

  • 301-Weiterleitungen für alle geänderten URLs
  • robots.txt überprüft und erlaubt das Crawlen
  • noindex-Tag nicht aus der Staging-Umgebung übrig geblieben
  • Sitemap.xml aktualisiert und in der Search Console registriert
  • Alle neuen URLs über die Indexing API eingereicht
  • Gelöschte Seiten mit URL_DELETED eingereicht
  • Überwachung der Search Console konfiguriert
