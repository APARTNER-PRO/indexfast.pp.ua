Website-Geschwindigkeit und SEO: Core Web Vitals, LCP, INP, CLS im Jahr 2026

Google berücksichtigt seit 2021 offiziell die Core Web Vitals bei der Bewertung. LCP, INP, CLS — drei Metriken, die bestimmen, ob Ihre Website einen Bonus oder eine Strafe in der Suche erhält. Wir analysieren jede Metrik, die Ursachen für schlechte Leistungen und spezifische Lösungen.

Warum die Geschwindigkeit der Website für SEO entscheidend ist

Seit 2021 berücksichtigt Google offiziell die Core Web Vitals bei der Bewertung — dies sind Geschwindigkeits- und Benutzerfreundlichkeitsmetriken, die unter realen Bedingungen auf tatsächlichen Benutzergeräten gemessen werden. Websites, die die Core Web Vitals-Schwelle überschreiten, erhalten einen kleinen Ranking-Vorteil.

Aber der indirekte Einfluss ist wichtiger: langsame Website → höhere Absprungrate → weniger Zeit auf der Seite → schlechtere Verhaltenssignale → niedrigere Rankings. Darüber hinaus weist Google langsamen Websites ein kleineres Crawl-Budget zu.

Core Web Vitals: Drei Schlüsselmetriken

LCP — Largest Contentful Paint

Die Zeit bis das größte sichtbare Element (normalerweise ein Hauptbild oder eine Überschrift) erscheint. Zeigt, wann der Benutzer den Hauptinhalt sieht.

  • Gut: bis zu 2,5 Sekunden
  • Verbesserungsbedarf: 2,5–4 s
  • Schlecht: über 4 Sekunden

Hauptursachen für schlechtes LCP: große unkomprimierte Bilder, langsamer Server, render-blockierende Ressourcen (JS, CSS), fehlendes CDN.

INP — Interaction to Next Paint

Reaktionszeit auf eine Benutzerinteraktion (Klick, Tippen, Eingabe). Ersetzte FID im März 2024.

  • Gut: bis zu 200 ms
  • Verbesserungsbedarf: 200–500 ms
  • Schlecht: über 500 ms

CLS — Cumulative Layout Shift

Gesamtes Verschieben von Elementen während des Ladens. Inhalte "springen", wenn Bilder oder Werbung geladen werden.

  • Gut: bis zu 0,1
  • Verbesserungsbedarf: 0,1–0,25
  • Schlecht: über 0,25
🔧 So überprüfen Sie es

pagespeed.web.dev — geben Sie die URL ein und erhalten Sie einen detaillierten Bericht über alle drei Metriken für mobile und Desktop-Versionen. Überprüfen Sie auch die Search Console → Core Web Vitals für Daten von echten Geräten.

Bildoptimierung — Der schnellste Gewinn

Bilder sind der Hauptgrund für ein langsames LCP. Einige Regeln:

  • WebP-Format — 25–35% kleiner als JPEG bei gleicher Qualität
  • Lazy Loading — loading="lazy" für Bilder unterhalb der Falz
  • Dimensionen in HTML — immer Breite und Höhe angeben, um CLS zu vermeiden
  • Preload LCP-Bild — fügen Sie <link rel="preload" as="image"> für das Hauptbild hinzu
  • CDN für Bilder — Cloudflare Images oder ein Äquivalent für globale Lieferung

Servergeschwindigkeit und TTFB

TTFB (Time to First Byte) — Zeit bis zum ersten Byte der Serverantwort. Google betrachtet einen TTFB von bis zu 800 ms als gut.

  • Caching — Seiten sollten aus dem Cache zurückgegeben werden, nicht jedes Mal neu generiert werden
  • Hosting — VPS oder Cloud-Hosting ist viel schneller als Shared Hosting
  • CDN — Cloudflare reduziert kostenlos den TTFB für Besucher aus verschiedenen Ländern
  • Datenbanken — langsame SQL-Abfragen sind die häufigste Ursache für schlechten TTFB

JavaScript- und CSS-Optimierung

Der Browser kann die Seite nicht rendern, während render-blockierende Ressourcen heruntergeladen und ausgeführt werden:

  • Bewegen Sie JS ans Ende des Body oder fügen Sie defer / async hinzu
  • Extrahieren Sie kritisches CSS (above-the-fold) und betten Sie es im Head ein
  • Minimieren und komprimieren Sie JS- und CSS-Dateien
  • Entfernen Sie ungenutztes CSS (Coverage-Registerkarte in DevTools)
  • Teilen Sie großes JS in Chunks auf und laden Sie es lazy
⚠ Drittanbieter-Skripte — Der Hauptfeind der Geschwindigkeit

Google Analytics, Facebook Pixel, Chats, Werbenetzwerke — jedes Drittanbieter-Skript fügt 100–500 ms zur Ladezeit hinzu. Die Überprüfung von Drittanbieter-Skripten über die Lighthouse-Netzwerk-Registerkarte ist ein obligatorischer Schritt.

Schriften und Geschwindigkeit

  • Verwenden Sie font-display: swap — Text ist sofort sichtbar, Schriftart wird im Hintergrund geladen
  • Preconnect zu fonts.googleapis.com und fonts.gstatic.com
  • Begrenzen Sie Schriftartenvarianten — nur die Gewichte, die tatsächlich verwendet werden
  • Erwägen Sie Systemschriftarten für kritischen Text (null Ladezeit)

Mobile Optimierung

Google verwendet Mobile-First-Indexierung — es indiziert die mobile Version der Website als die primäre. Daher ist die mobile Geschwindigkeit wichtiger als die Desktop-Geschwindigkeit.

  • Überprüfen Sie die mobile PageSpeed separat von der Desktop-Version
  • Testen Sie auf echten Geräten, nicht nur in DevTools
  • Schaltflächen mindestens 48x48px für einfaches Tippen
  • Vermeiden Sie horizontales Scrollen
  • Popups sollten den Hauptinhalt nicht verdecken (Strafe für aufdringliche Interstitials)

Checkliste zur Website-Geschwindigkeit

  • LCP unter 2,5 Sekunden auf Mobilgeräten
  • INP unter 200 ms
  • CLS unter 0,1
  • Alle Bilder im WebP-Format
  • Lazy Loading für Bilder unterhalb der Falz
  • CDN verbunden (Cloudflare oder Äquivalent)
  • JS ans Ende verschoben oder defer hinzugefügt
  • Server-Caching konfiguriert
  • TTFB unter 800 ms
  • font-display: swap für benutzerdefinierte Schriftarten
  • Überprüfung von Drittanbieter-Skripten abgeschlossen
