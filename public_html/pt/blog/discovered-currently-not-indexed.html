"Descoberto, atualmente não indexado": por que o Google ignora as suas páginas e como resolver

Abre o Google Search Console e vê uma lista de páginas com o estado "Descoberto — atualmente não indexado". Os dias passam, as semanas passam — as páginas ainda não estão no Google. Este é um dos problemas mais frustrantes para os proprietários de sites. Explicamos exatamente por que isso acontece e como resolver de uma vez por todas.

O que realmente significa "Descoberto — atualmente não indexado"

Este estado significa que o Google encontrou o URL — através do seu sitemap ou de um link — mas decidiu não rastreá-lo ainda. Em outras palavras: o Google sabe que a página existe, mas escolheu não visitá-la.

A palavra-chave aqui é "escolheu". Não é um erro técnico. É uma decisão de agendamento do Google baseada no crawl budget do seu site e na prioridade percebida dessa página.

💡 Analogia simples

Imagine um carteiro que tem 1.000 cartas para entregar. Ele conhece o seu endereço, mas se acha que a entrega é de baixa prioridade, coloca a carta no final da fila. A sua página espera meses enquanto as páginas dos concorrentes são indexadas no mesmo dia.

As razões reais pelas quais o Google ignora as suas páginas

A maioria dos guias de SEO dá respostas vagas como "melhore a qualidade do conteúdo". A verdade é mais específica:

  • Crawl budget esgotado. O Google aloca um número limitado de rastreamentos por site por dia. Sites grandes com milhares de páginas frequentemente esgotam o orçamento.
  • Baixa autoridade de domínio. Sites novos ou com poucos backlinks recebem um crawl budget menor.
  • Tempos de resposta do servidor lentos. Se o seu servidor responde lentamente (acima de 500ms), o rastreador do Google abranda ou para.
  • Demasiadas páginas de baixo valor. Páginas de filtros paginadas, páginas de tags ou conteúdo duplicado "desperdiçam" o orçamento do Google.
  • Sem links internos. Páginas que existem apenas no sitemap mas não têm links internos são consideradas de baixa prioridade.
  • Publicada recentemente. Novas páginas em sites de baixa autoridade podem esperar meses na fila "descoberto".

O que NÃO fazer (erros comuns)

Quando os proprietários veem este estado, frequentemente pioram as coisas:

  • Solicitar constantemente a reindexação através de "Inspeção de URL" no Search Console (limite de apenas 10-15 URLs por dia manualmente)
  • Bloquear e desbloquear páginas no robots.txt esperando um novo rastreamento
  • Remover páginas do sitemap pensando que isso vai ajudar
  • Esperar indefinidamente sem ação — isso pode durar meses
⚠ A armadilha da inspeção manual de URL

O botão "Solicitar indexação" no Search Console parece uma solução, mas tem limites muito restritos. Pode enviar talvez 10-15 URLs por dia desta forma. Para um site com centenas de páginas afetadas, isso é praticamente inútil.

A solução real: forçar o Google a indexar através da API oficial

O Google fornece a Indexing API especificamente para permitir que os sites notifiquem o Google sobre páginas importantes que precisam de rastreamento imediato. Quando envia um pedido através da API, o Google prioriza o rastreamento desse URL — tipicamente dentro de 24-48 horas.

Não é uma solução alternativa nem uma técnica de chapéu cinzento. É o método oficialmente recomendado pelo Google para acelerar a indexação.

Passo 1: Configure corretamente o Google Search Console

Verifique o seu site no Google Search Console. Certifique-se de ter um sitemap bem estruturado enviado. Verifique penalidades manuais em "Ações manuais".

Passo 2: Corrija os problemas técnicos primeiro

Antes de forçar a indexação, corrija o que está partido: páginas que carregam em menos de 3 segundos, adicione links internos a páginas órfãs, remova páginas de baixo valor do seu sitemap.

Passo 3: Use a Google Indexing API para enviar páginas

Aqui é onde a aceleração real acontece. Através da Indexing API pode notificar o Google de 200 URLs por dia — o Google então envia o Googlebot para rastrear esses URLs específicos com alta prioridade. A diferença:

❌
Sem API: 2-8 semanas
✅
Com API: 24-48 horas

Como fazer isso sem escrever código

Configurar manualmente a Google Indexing API requer: criar um projeto Google Cloud, uma conta de serviço, baixar credenciais JSON, escrever chamadas API e configurar a automação. Para não desenvolvedores, esta é uma barreira técnica significativa.

  • Mostra um registo detalhado de quais páginas foram submetidas e quando

Que páginas priorizar primeiro

Não tente indexar tudo de uma vez. Com uma quota de 200 URLs/dia, seja estratégico:

  1. Primeiro as páginas que geram receita — páginas de produtos, serviços, landing pages
  2. Conteúdo fresco — novos posts de blog, artigos de notícias
  3. Páginas recentemente atualizadas — se alterou significativamente conteúdo existente
  4. Ignore páginas de conteúdo escasso — resultados paginados, páginas de tags, combinações de filtros

A longo prazo: evite que o estado "Descoberto" volte a acontecer

Depois de resolver o seu acumulado atual, configure um sistema para que as novas páginas nunca mais fiquem presas:

  • Indexação automática diária: Configure o IndexFast para verificar o seu sitemap todos os dias e enviar automaticamente os novos URLs.
  • Links internos: Quando publicar novo conteúdo, faça um link para ele a partir de 2-3 páginas populares existentes.
  • Higiene do sitemap: Remova páginas que não quer indexadas (conteúdo escasso, duplicados) do seu sitemap.
  • Monitorize o Search Console: Verifique semanalmente Cobertura > "Descoberto — atualmente não indexado". Se os números aumentam, investigue imediatamente.
