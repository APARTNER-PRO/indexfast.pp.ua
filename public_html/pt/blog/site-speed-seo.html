Velocidade do Site e SEO: Core Web Vitals, LCP, INP, CLS em 2026

O Google considera oficialmente os Core Web Vitals na classificação desde 2021. LCP, INP, CLS — três métricas que determinam se seu site recebe um bônus ou uma penalidade na busca. Analisamos cada métrica, as causas de um desempenho ruim e soluções específicas.

Por que a Velocidade do Site é Crítica para o SEO

Desde 2021, o Google considera oficialmente os Core Web Vitals para classificação — essas são métricas de velocidade e usabilidade medidas em condições reais em dispositivos reais dos usuários. Sites que passam o limite dos Core Web Vitals recebem um pequeno impulso na classificação.

Mas o impacto indireto é mais importante: site lento → maior taxa de rejeição → menos tempo na página → piores sinais comportamentais → classificações mais baixas. Além disso, o Google aloca um orçamento de rastreamento menor para sites lentos.

Core Web Vitals: Três Métricas Chave

LCP — Largest Contentful Paint

Tempo até o maior elemento visível (geralmente uma imagem principal ou título) aparecer. Mostra quando o usuário vê o conteúdo principal.

  • Bom: até 2,5 segundos
  • Precisa de melhorias: 2,5–4 s
  • Ruim: mais de 4 segundos

Principais causas de um LCP ruim: imagens grandes não compactadas, servidor lento, recursos que bloqueiam a renderização (JS, CSS), falta de CDN.

INP — Interaction to Next Paint

Tempo de resposta a uma interação do usuário (clique, toque, entrada). Substituiu o FID em março de 2024.

  • Bom: até 200 ms
  • Precisa de melhorias: 200–500 ms
  • Ruim: mais de 500 ms

CLS — Cumulative Layout Shift

Deslocamento total de elementos durante o carregamento. O conteúdo "salta" quando imagens ou anúncios são carregados.

  • Bom: até 0,1
  • Precisa de melhorias: 0,1–0,25
  • Ruim: mais de 0,25
🔧 Como Verificar

pagespeed.web.dev — insira a URL e obtenha um relatório detalhado sobre todas as três métricas para dispositivos móveis e desktop. Além disso, verifique o Search Console → Core Web Vitals para dados de dispositivos reais.

Otimização de Imagens — A Vitória Mais Rápida

Imagens são a principal razão para um LCP lento. Algumas regras:

  • Formato WebP — 25–35% menor que JPEG na mesma qualidade
  • Lazy loading — loading="lazy" para imagens abaixo da dobra
  • Dimensões em HTML — sempre especifique largura e altura para evitar CLS
  • Pré-carregar imagem LCP — adicione <link rel="preload" as="image"> para a imagem principal
  • CDN para imagens — Cloudflare Images ou equivalente para entrega global

Velocidade do Servidor e TTFB

TTFB (Time to First Byte) — tempo até o primeiro byte da resposta do servidor. O Google considera um TTFB de até 800ms como bom.

  • Cache — as páginas devem ser retornadas do cache, não geradas toda vez
  • Hospedagem — VPS ou hospedagem em nuvem é muito mais rápida que compartilhada
  • CDN — Cloudflare reduz o TTFB para visitantes de diferentes países gratuitamente
  • Bancos de dados — consultas SQL lentas são a causa mais frequente de um TTFB ruim

Otimização de JavaScript e CSS

O navegador não pode renderizar a página enquanto recursos que bloqueiam a renderização estão sendo baixados e executados:

  • Mova o JS para o final do body ou adicione defer / async
  • Extraia o CSS crítico (acima da dobra) e insira-o no head
  • Minimize e comprima arquivos JS e CSS
  • Remova CSS não utilizado (aba Coverage no DevTools)
  • Divida grandes arquivos JS em chunks e carregue-os de forma preguiçosa
⚠ Scripts de Terceiros — O Principal Inimigo da Velocidade

Google Analytics, Facebook Pixel, chats, redes de anúncios — cada script de terceiros adiciona 100–500ms ao tempo de carregamento. Auditar scripts de terceiros através da aba Network do Lighthouse é um passo obrigatório.

Fontes e Velocidade

  • Use font-display: swap — o texto é visível imediatamente, a fonte carrega em segundo plano
  • Pré-conecte-se a fonts.googleapis.com e fonts.gstatic.com
  • Limite as variantes de fontes — apenas os pesos que são realmente utilizados
  • Considere fontes do sistema para texto crítico (tempo de carregamento zero)

Otimização Móvel

O Google usa Indexação Mobile-First — ele indexa a versão móvel do site como a principal. Portanto, a velocidade móvel é mais importante que a desktop.

  • Verifique o PageSpeed móvel separadamente do desktop
  • Teste em dispositivos reais, não apenas no DevTools
  • Botões com no mínimo 48x48px para fácil toque
  • Evite rolagem horizontal
  • Pop-ups não devem obscurecer o conteúdo principal (penalidade por intersticiais intrusivos)

Checklist de Velocidade do Site

  • LCP abaixo de 2,5 segundos em dispositivos móveis
  • INP abaixo de 200ms
  • CLS abaixo de 0,1
  • Todas as imagens no formato WebP
  • lazy loading para imagens abaixo da dobra
  • CDN conectado (Cloudflare ou equivalente)
  • JS movido para o final ou defer adicionado
  • Cache do servidor configurado
  • TTFB abaixo de 800ms
  • font-display: swap para fontes personalizadas
  • Auditoria de scripts de terceiros concluída
