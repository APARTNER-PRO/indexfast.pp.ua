Чому WordPress сайти часто мають проблеми з індексацією

WordPress — найпопулярніша CMS у світі, але її стандартні налаштування не оптимізовані для SEO. Сотні тисяч WordPress сайтів мають однакові типові помилки: сторінки тегів дублюють контент, архіви авторів виводять ті самі статті, пагінація не налаштована.

Хороша новина: більшість проблем вирішуються за 15–30 хвилин через плагіни Yoast SEO або RankMath.

Yoast SEO: базові налаштування для індексації

Yoast SEO → Зовнішній вигляд → Типи контенту:

  • Статті (Posts) — index: Так, Show in results: Так
  • Сторінки (Pages) — index: Так
  • Медіа (Attachments) — index: Ні (вимкнути обов'язково)
  • Теги (Tags) — index: Ні якщо менше 5 статей на тег
  • Архіви авторів — index: Ні якщо один автор
⚠ Медіа-сторінки — прихований дублювач

WordPress за замовчуванням створює окрему сторінку для кожного завантаженого зображення (attachment page). Ці сторінки — майже порожній контент і серйозно витрачають crawl budget. Вимкніть їх в Yoast SEO → Зовнішній вигляд → Медіа → вимкнути attachment pages.

Теги і категорії

WordPress теги — одна з найбільших SEO-пасток. Кожен тег створює окрему сторінку-архів, яка виводить ті самі статті що і категорія. Результат: дублі контенту і розмивання crawl budget.

  • Якщо тег використовується менше ніж на 5 статтях → noindex або видаліть
  • Якщо категорія і тег виводять однаковий контент → видаліть теги взагалі
  • Для активних тегів: додайте унікальний опис через Yoast (мінімум 100 слів)

XML Sitemap в WordPress

WordPress 5.5+ має вбудований sitemap (/wp-sitemap.xml), але він включає все підряд: attachment pages, порожні архіви, сторінки авторів. Краще використовувати Yoast SEO sitemap:

  • Yoast SEO автоматично виключає сторінки з noindex
  • Дозволяє окремо налаштувати що включати
  • Автоматично оновлюється при публікації нових матеріалів
https://yoursite.com/sitemap_index.xml ← Yoast sitemap index https://yoursite.com/post-sitemap.xml ← статті https://yoursite.com/page-sitemap.xml ← сторінки https://yoursite.com/category-sitemap.xml ← категорії

Швидкість WordPress і SEO

Повільний WordPress сайт отримує менший crawl budget і гірше ранжується. Основні причини повільної роботи:

  • Занадто багато плагінів (особливо візуальних конструкторів)
  • Неоптимізовані зображення без WebP
  • Відсутність кешування (WP Super Cache, W3 Total Cache)
  • Повільний хостинг або спільний сервер

Типові помилки WordPress в Search Console

  • «Виявлено, але не проіндексовано» — зазвичай низькоякісні сторінки або crawl budget проблема
  • «Дублювана без канонічного тегу» — www і non-www версії, або параметри URL
  • «Crawler anomaly» — плагін або тема генерує помилкові URL
  • «Soft 404» — сторінка виглядає порожньою але повертає код 200
