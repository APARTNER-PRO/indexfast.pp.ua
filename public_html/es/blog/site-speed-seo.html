Velocidad del sitio y SEO: Core Web Vitals, LCP, INP, CLS en 2026

Google ha considerado oficialmente los Core Web Vitals en el ranking desde 2021. LCP, INP, CLS — tres métricas que determinan si tu sitio recibe un bono o una penalización en la búsqueda. Analizamos cada métrica, las causas del bajo rendimiento y soluciones específicas.

Por qué la velocidad del sitio es crítica para el SEO

Desde 2021, Google considera oficialmente los Core Web Vitals para el ranking — estas son métricas de velocidad y usabilidad medidas en condiciones reales en dispositivos reales de los usuarios. Los sitios que superan el umbral de Core Web Vitals reciben un ligero impulso en el ranking.

Pero el impacto indirecto es más importante: sitio lento → mayor tasa de rebote → menos tiempo en la página → peores señales de comportamiento → clasificaciones más bajas. Además, Google asigna un presupuesto de rastreo más pequeño a los sitios lentos.

Core Web Vitals: Tres métricas clave

LCP — Largest Contentful Paint

Tiempo hasta que aparece el elemento visible más grande (generalmente una imagen principal o un encabezado). Muestra cuándo el usuario ve el contenido principal.

  • Bueno: hasta 2.5 segundos
  • Necesita mejora: 2.5–4 s
  • Pobre: más de 4 segundos

Causas principales de un mal LCP: imágenes grandes sin comprimir, servidor lento, recursos que bloquean el renderizado (JS, CSS), falta de CDN.

INP — Interaction to Next Paint

Tiempo de respuesta a una interacción del usuario (clic, toque, entrada). Reemplazó a FID en marzo de 2024.

  • Bueno: hasta 200 ms
  • Necesita mejora: 200–500 ms
  • Pobre: más de 500 ms

CLS — Cumulative Layout Shift

Desplazamiento total de elementos durante la carga. El contenido "salta" cuando se cargan imágenes o anuncios.

  • Bueno: hasta 0.1
  • Necesita mejora: 0.1–0.25
  • Pobre: más de 0.25
🔧 Cómo comprobar

pagespeed.web.dev — ingresa la URL y obtén un informe detallado sobre las tres métricas para móvil y escritorio. Además, verifica Search Console → Core Web Vitals para datos de dispositivos reales.

Optimización de imágenes — La victoria más rápida

Las imágenes son la principal razón de un LCP lento. Algunas reglas:

  • Formato WebP — 25–35% más pequeño que JPEG con la misma calidad
  • Carga diferida — loading="lazy" para imágenes debajo del pliegue
  • Dimensiones en HTML — siempre especifica el ancho y la altura para evitar CLS
  • Precargar imagen LCP — agrega <link rel="preload" as="image"> para la imagen principal
  • CDN para imágenes — Cloudflare Images o un equivalente para entrega global

Velocidad del servidor y TTFB

TTFB (Time to First Byte) — tiempo hasta el primer byte de la respuesta del servidor. Google considera un TTFB de hasta 800 ms como bueno.

  • Cacheo — las páginas deben ser devueltas desde la caché, no generadas cada vez
  • Alojamiento — VPS o alojamiento en la nube es mucho más rápido que compartido
  • CDN — Cloudflare reduce el TTFB para visitantes de diferentes países de forma gratuita
  • Bases de datos — consultas SQL lentas son la causa más frecuente de un mal TTFB

Optimización de JavaScript y CSS

El navegador no puede renderizar la página mientras se están descargando y ejecutando recursos que bloquean el renderizado:

  • Mueve JS al final del body o agrega defer / async
  • Extrae CSS crítico (above-the-fold) e insértalo en el head
  • Minimiza y comprime archivos JS y CSS
  • Elimina CSS no utilizado (pestaña Coverage en DevTools)
  • Divide JS grande en fragmentos y cárgalos de forma diferida
⚠ Scripts de terceros — El principal enemigo de la velocidad

Google Analytics, Facebook Pixel, chats, redes publicitarias — cada script de terceros añade 100–500 ms al tiempo de carga. Auditar scripts de terceros a través de la pestaña Lighthouse Network es un paso obligatorio.

Fuentes y velocidad

  • Usa font-display: swap — el texto es visible inmediatamente, la fuente se carga en segundo plano
  • Preconectar a fonts.googleapis.com y fonts.gstatic.com
  • Limita las variantes de fuentes — solo aquellos pesos que realmente se utilizan
  • Considera fuentes del sistema para texto crítico (tiempo de carga cero)

Optimización móvil

Google utiliza la indexación Mobile-First — indexa la versión móvil del sitio como la principal. Por lo tanto, la velocidad móvil es más importante que la de escritorio.

  • Verifica la velocidad de la página móvil por separado de la de escritorio
  • Prueba en dispositivos reales, no solo en DevTools
  • Botones de mínimo 48x48px para un toque fácil
  • Evita el desplazamiento horizontal
  • Los popups no deben oscurecer el contenido principal (penalización por intersticiales intrusivos)

Lista de verificación de velocidad del sitio

  • LCP por debajo de 2.5 segundos en móvil
  • INP por debajo de 200 ms
  • CLS por debajo de 0.1
  • Todas las imágenes en formato WebP
  • carga diferida para imágenes debajo del pliegue
  • CDN conectado (Cloudflare o equivalente)
  • JS movido al final o agregado defer
  • Cacheo del servidor configurado
  • TTFB por debajo de 800 ms
  • font-display: swap para fuentes personalizadas
  • Auditoría de scripts de terceros completada
